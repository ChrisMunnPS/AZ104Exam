AZ-104 cheat sheet 1/5 — Manage Azure identities and governance

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Tenants, subscriptions, and hierarchy

ItemWhat to remember
Resource hierarchyManagement group → subscription → resource group → resource. Policy and RBAC inherit downward only.
Tenant vs subscriptionA tenant (Entra ID) holds identities; a subscription is a billing and scale boundary that trusts one tenant.
Multiple subscriptionsBilling scopes (billing account → invoice section → subscription) are separate from the resource hierarchy. Move subscriptions between management groups freely.
Management groupsUp to 6 levels below the tenant root, 10,000 per directory; a group or subscription has exactly one parent.
Moving resourcesMoving to a new resource group keeps the resource ID's RG segment; moving to a new subscription changes the whole ID. Both sides must be in the same region for most types.
Region moveNot supported by "move" for most services — redeploy from a template, or use Azure Resource Mover.
Resource group rulesA resource lives in exactly one RG. Deleting the RG deletes everything in it. RGs cannot be nested.
Naming and tagsTags are not inherited from RG or subscription. A policy with the Modify effect can add or inherit them.

Microsoft Entra users and groups

ItemWhat to remember
User typesMember (in tenant) vs Guest (B2B). userType is informational; authorization comes from role assignments.
Create usersPortal, Microsoft Graph PowerShell, Azure CLI (az ad user create), bulk CSV import (max 50,000 rows).
Delete and restoreDeleted users stay restorable for 30 days with the same object ID.
GroupsSecurity groups grant access only. Microsoft 365 groups add mailbox, calendar, SharePoint, Teams. Mail-enabled security does both.
MembershipAssigned (manual) or dynamic (rule on attributes). Dynamic membership is read-only; you cannot add members by hand.
Dynamic rule limitsOne rule per group; no nesting of groups; the owner of the attribute can change membership.
Role-assignable groupsCreated with isAssignableToRole = true; cannot be converted afterwards, and cannot be dynamic.
LicencesGroup-based licensing needs a usage location on every user. Removing a member removes the licence.
Licence errorsNot enough licences · usage location missing · conflicting service plans · dependent add-on missing.
SSPRNeeds P1/P2 for on-prem writeback; administrators always need two methods; writeback requires Entra Connect.
External usersInvite by email; the guest redeems in their home tenant. Cross-tenant access settings control inbound and outbound trust.
Entra Domain ServicesManaged domain for legacy LDAP/Kerberos/NTLM workloads; no domain-admin rights; one-way sync from Entra ID.

Azure RBAC

ItemWhat to remember
Assignment partsSecurity principal + role definition + scope. Permissions = Actions − NotActions, then deny assignments win.
Built-in rolesOwner (full + grant access) · Contributor (full, no grant) · Reader · User Access Administrator (grant only) · Role Based Access Control Administrator (grant, no data access).
Scope choiceAssign at the highest scope that still satisfies least privilege; group membership beats per-user assignments.
Deny assignmentsCreated by managed apps and Blueprints, not by you. They block even Owners and cannot be overridden.
Custom rolesJSON with Actions, NotActions, DataActions, AssignableScopes. One subscription per custom role by default; add all scopes you need.
Effective accessCheck Access control (IAM) → Check access, or the Effective permissions blade, before troubleshooting.
Classic administratorsCo-administrator and Service Administrator are legacy; migrate to RBAC.
AuditRole assignment changes appear in the Activity log; sign-ins in Entra sign-in logs.

Azure Policy

ItemWhat to remember
Definitions and initiativesA policy definition is one rule; an initiative groups definitions for one assignment. Assign at management group for the widest reach.
EffectsDeny, Audit, Append, Modify, DeployIfNotExists, AuditIfNotExists, Disabled. Deny blocks new and updated resources only.
RemediationdeployIfNotExists and modify need a managed identity and a remediation task. Existing non-compliant resources are not fixed automatically.
ExemptionsNot required (waiver) or Mitigated (category + expiry). Exemptions are auditable and time-bounded.
ComplianceEvaluation runs about every 24 hours, or on demand. The compliance pane shows per-resource and per-policy state.
Policy vs RBACRBAC controls who can do what; Policy controls what the result may look like.

Locks, cost, and tooling

ItemWhat to remember
Resource locksCanNotDelete and ReadOnly. They apply to the scope and everything below; ReadOnly blocks reads of keys/secrets in some services.
Lock ownershipLocks are inherited from the parent scope. A lock does not stop a deny assignment or a policy.
Cost toolsCost analysis (slice by tag/RG/resource), budgets (alert at a threshold), Advisor recommendations, exports to storage.
Azure AdvisorReliability, security, performance, cost, operational excellence — free, per subscription.
CLI vs PowerShellaz (Bash/PowerShell) and Az module. az role assignment create / New-AzRoleAssignment; az policy assignment create / New-AzPolicyAssignment.
Sign-in blockingaz ad user update --account-enabled false or Update-MgUser -AccountEnabled:$false. Requires User Administrator or higher.

AZ-104 cheat sheet 2/5 — Implement and manage storage

One page. Facts snapshot 2026-11; verify current behaviour on Microsoft Learn before the exam.

Storage accounts

ItemWhat to remember
Account kindsStandard general-purpose v2 (blobs, files, queues, tables) · Premium block blobs · Premium file shares (FileStorage) · Premium page blobs.
Performance tiersStandard uses HDD-backed capacity; premium uses SSD. A standard account can change access tier per blob, not per account performance tier.
Replication at createChoose LRS/ZRS/GRS/RA-GRS (or GZRS/RA-GZRS). Changing later is possible in one direction only for some paths — plan first.
Naming3–24 characters, lowercase letters and numbers only, globally unique.
Endpointshttps://<account>.blob.core.windows.net, .file., .queue., .table..
Limits5 PiB per standard account (soft), 500 TiB per premium block blob account.
Network accessPublic from all networks · public from selected virtual networks and IP addresses · private endpoint. Setting "selected networks" disables the other paths unless you add them.
Require secure transferForces HTTPS. Disable only for legacy SMB 2.1 or HTTP-only clients.
Minimum TLSSet to TLS 1.2 (1.3 where supported).

Redundancy

OptionCopiesSurvives
LRS3 in one datacenterDisk and rack failure
ZRS3 across three zones in one regionZone failure
GRSLRS + 3 asynchronous copies in the paired regionRegion failure (no read access until failover)
RA-GRSGRS + read-only access to the secondary endpointRegion failure with read access
GZRSZRS + 3 asynchronous copies in the paired regionZone and region failure
RA-GZRSGZRS + readable secondaryZone and region failure with read access
File sharesPremium FileStorage supports LRS and ZRS only — no GRS. Azure Files has no readable secondary endpoint.

Access and security

ItemWhat to remember
Shared key vs EntraShared key authorizes with the account keys and bypasses RBAC and file/directory ACLs. Set Allow storage account key access = Disabled to force Entra ID.
Azure Files identityEntra Domain Services, Entra Kerberos (cloud-only, hybrid), or on-prem AD DS over SMB. Needs a usage location-style prerequisite check and the right share-level role.
Blob data rolesStorage Blob Data Reader / Contributor / Owner. Control-plane roles (Contributor) do not grant blob data access.
SAS typesAccount SAS (services + resource types) · Service SAS (one service) · User delegation SAS (Entra-backed, blobs only, max 7 days).
Stored access policyUp to 5 per container or share. Revoke by deleting or editing the policy — a service SAS without a policy cannot be revoked early.
SAS best practiceShort expiry, least permissions, HTTPS only, stored access policy when revocation matters, user delegation over account key.
KeysTwo keys per account for rotation. Rotate in Key Vault-backed flows; regenerating a key invalidates every SAS and client using it.
EncryptionPlatform-managed keys by default; customer-managed keys in Key Vault for blob/file encryption at rest; infrastructure encryption adds a second layer.
Encryption scopeApplies a distinct CMK to a container or blob instead of the whole account.

Azure Files

ItemWhat to remember
ProtocolsSMB 3.x (Windows/Linux/macOS) and NFS 4.1 (premium only, no Windows, no identity-based auth).
TiersTransaction optimized · Hot · Cool (standard only); premium is provisioned by capacity.
SnapshotsRead-only point-in-time copies of a share. Restore a file from a snapshot with Previous Versions or Restore-AzStorageFileCopy.
Soft deleteRetains deleted shares for 1–365 days; file-level soft delete is separate.
BackupAzure Backup for Azure Files uses a snapshot-based policy; the vault can be Recovery Services or Backup vault.
Limits100 TiB per share on standard (large file shares enabled) and premium; IOPS scale with provisioned size on premium.

Blobs

ItemWhat to remember
Access tiersHot · Cool (30-day min) · Cold (90-day min) · Archive (180-day min, offline). Early deletion charges apply.
RehydrateArchive → Hot/Cool is Standard (hours) or High (under an hour, higher cost).
Lifecycle policyRules with filters (prefix, blob type, tier) and actions (tier, delete, snapshot delete). Runs once a day; changes can take 24–48 h.
VersioningAutomatic previous versions on every write. Combined with soft delete for recovery; both are needed for ransomware protection.
Soft deleteBlob 1–365 days, container 7–365 days, file share 1–365 days.
Immutable storageTime-based retention (WORM) or legal hold. A locked policy cannot be removed or shortened.
Object replicationAsynchronous copy blob to blob between accounts; needs versioning on both, change feed on the source, and no immutability on the destination.
Access levelsPrivate (default) · Blob (anonymous read of blobs) · Container (anonymous list). Container access is usually blocked by policy.

Tooling

ToolUse it for
AzCopyScripted, high-throughput copy. azcopy copy, azcopy sync, --recursive, SAS or Entra auth. No moves between tiers, but copies and then deletes with --delete-destination.
Storage ExplorerDesktop GUI; connects with Entra, SAS, key, or connection string. Can attach to emulator and to Data Lake.
Azure Storage MoverManaged migration service for large on-premises file and blob estates.
az storage / AzStorageControl-plane and data-plane commands; az storage blob upload-batch, Get-AzStorageBlob.

AZ-104 cheat sheet 3/5 — Deploy and manage Azure compute resources

ARM templates and Bicep

ItemWhat to remember
Required sections$schema, contentVersion, resources. parameters, variables, outputs are optional.
IdempotencyRedeploying the same template with the same parameters produces the same result; existing matching resources are left alone.
Deployment modesIncremental (default; keeps resources not in the template) vs Complete (deletes them). Complete deletes resources in the scope, so use a dedicated RG.
ParameterssecureString and secureObject are not logged. Use allowedValues to constrain input and defaultValue to make a parameter optional.
DependenciesdependsOn for explicit ordering. Use reference()/resourceId() for implicit dependencies and outputs; circular dependencies fail validation.
ScoperesourceGroup (default), subscription, managementGroup, tenant. Nested or linked templates change the scope.
What-ifPreview create/modify/delete/ignore before deployment. Available in CLI, PowerShell, and the portal.
BicepCompiles to ARM JSON. az bicep build / bicep build. bicep decompile is best-effort and usually needs cleanup.
ModulesOne Bicep file per reusable unit; pass params, take outputs. Registry modules come from ACR.
ExportPortal Export template only covers resources in that RG and loses some properties; not a substitute for source control.

Virtual machines

ItemWhat to remember
SizesB (burstable) · D (general) · E (memory optimised) · F (compute optimised) · N (GPU) · L (storage). The letter is the family, the number is the vCPU count.
ResizeRequires a deallocate first unless the new size is available on the same host. Cross-family resize may need a redeploy.
DisksOS disk (Premium SSD, Standard SSD, Standard HDD, ephemeral) · data disks · Ultra disk (needs a zone, no host caching, only certain sizes).
Ephemeral OS diskUses local VM storage; no storage cost; lost on deallocate. Good for stateless scale sets.
Disk cachingReadOnly suits read-heavy data; None for write-heavy or Ultra. ReadWrite is not allowed on some sizes.
EncryptionAzure Disk Encryption (BitLocker/DM-Crypt, uses Key Vault) vs encryption at host vs server-side encryption with a CMK. ADE requires a key vault.
ExtensionsCustom Script, DSC, Azure Monitor Agent, VM Backup. Order with dependsOn; the agent runs as SYSTEM/root.
NetworkingEach VM needs a NIC in a subnet. NSG can sit on the subnet or the NIC; both are evaluated.
Availability setUp to 3 fault domains and 20 update domains (default 5). Protects against host and rack failure inside one datacenter only.
Availability zonePhysically separate datacenter in the region; three in every enabled region. Protects against a datacenter loss.
SLASingle VM with premium disks: 99.9% · availability set: 99.95% · zones: 99.99%.

Scale sets

ItemWhat to remember
OrchestrationUniform (identical instances, VMSS-managed) vs Flexible (mix of VMSS and standalone VMs, no uniform guarantees).
Zone spanningA uniform set can span zones (max 3) but not be both zonal and regional.
AutoscaleMetric rules (CPU, memory via agent, queue length) or schedule. Set min, max, and default count.
Cool-downAfter a scale action the rule waits cooldown (default 5 min) before acting again.
Scale-in policyDefault · Newest VM · Oldest VM. Protect instances that must not be removed.
Upgrade policyManual · Automatic (all at once, may cause downtime) · Rolling (batch + pause, honours health probes) · Canary (Flexible).
OverprovisioningCreates extra instances then deletes them; speeds deployment but costs briefly. Disable for large or costly SKUs.
HealthApplication health extension or a load balancer probe drives rolling upgrades and automatic instance repair.

Containers

ItemWhat to remember
ACIServerless container group; fastest to start; no orchestrator; per-second billing. Good for short batch jobs and burst.
Container groupOne or more containers sharing a host, network namespace, and storage. Restart policy: Always, OnFailure, Never.
ACI networkingOptional VNet injection with a delegated subnet; otherwise a public IP or no IP at all.
ACRPrivate registry. Tiers: Basic, Standard, Premium (geo-replication, private link, content trust).
ACR authdocker login with the admin account (avoid), a service principal, a managed identity, or az acr login.
Container AppsManaged Kubernetes-based serverless platform: scale to zero, revisions, traffic splitting, Dapr, KEDA rules.
AKSFull Kubernetes control; node pools, upgrade channels. AZ-104 only needs the basics.

App Service

ItemWhat to remember
PlansFree/Shared (no SLA) · Basic · Standard · Premium v3 · Isolated (ASE). Scale up = change plan; scale out = instance count.
SlotsStandard or higher. A swap warms the target slot then switches; slot settings (connection strings, app settings marked "slot setting") stay put.
Custom domainCNAME for a subdomain, A record + asuid TXT for the apex. Verify before adding.
TLSApp Service managed certificate (free, no wildcard, no apex) or upload a PFX. Enforce HTTPS with a redirect.
NetworkingAccess restrictions (allow/deny by IP or VNet) · VNet integration (outbound) · private endpoint (inbound) · Hybrid Connections.
BackupNeeds Standard or higher and a storage account in the same subscription. Backs up app content and configuration, not the database by default.
DeploymentZip deploy, GitHub Actions, Azure DevOps, az webapp deploy, run-from-package.
Always OnKeeps the app warm; required for continuous WebJobs. Not available on Free/Shared.

VNets and subnets

ItemWhat to remember
Address spaceRFC 1918 private ranges; can add several. Must not overlap any peered or connected network.
Reserved addresses5 per subnet: network, first host (gateway), two for Azure DNS, broadcast. A /24 has 251 usable.
Smallest subnet/29 (3 usable). GatewaySubnet should be /27 or larger; AzureBastionSubnet needs /26 or larger.
Reserved namesGatewaySubnet, AzureFirewallSubnet, AzureBastionSubnet, AzureFirewallManagementSubnet.
DelegationHands a subnet to a service (App Service, ACI, SQL Managed Instance). One delegation per subnet; no mixed workloads.
Adding a subnetAllowed while VMs are running. Changing the address space is allowed only if nothing is using the new range.

Peering and routing

ItemWhat to remember
PeeringPrivate, low-latency, both directions must be created; status must be Connected on both sides. Works across regions too, billed as egress. Fails if address spaces overlap.
Non-transitivityPeering is not transitive: A↔B and B↔C does not connect A to C. Use a hub with a firewall or NVA, or Azure Virtual WAN.
Gateway transitAllow gateway transit on the hub peering + Use remote gateways on the spoke. One gateway serves many spokes.
Service chainingA UDR in a spoke pointing 0.0.0.0/0 at a firewall in the hub gives inspection and transitive reachability.
UDR next hopsVirtual network gateway · Virtual network · Internet · Virtual appliance · None (blackhole).
Route selectionLongest prefix match first, then UDR over BGP over system route.
IP forwardingAn NVA NIC must have IP forwarding enabled, or packets are dropped.
Default routesAzure adds system routes for the VNet, peered VNets, and 0.0.0.0/0 → Internet. A UDR overrides the Internet route.

IP addressing

ItemWhat to remember
Public IP SKUsBasic (open by default, no zones, retiring) vs Standard (secure by default, static, zone-redundant or zonal, needs an NSG to allow inbound).
AllocationStatic or dynamic. Standard public IPs are always static.
Private IPDynamic or static per NIC. Changing it requires the NIC to be idle.

NSGs and ASGs

ItemWhat to remember
ScopeSubnet and/or NIC. Both are evaluated: inbound subnet then NIC, outbound NIC then subnet.
Default rulesAllow VNet inbound/outbound, allow Azure Load Balancer, deny all other inbound, allow Internet outbound. Cannot be deleted, only overridden by a higher-priority rule.
Priority100–4096, lower number wins. First match applies; no "deny all" needed unless you want one.
StatefulReturn traffic for an allowed flow is automatically allowed.
ASGGroups NICs by role (web, app, db). Rules then reference the ASG as source or destination instead of IP ranges.
Service tagsVirtualNetwork, AzureLoadBalancer, Internet, Storage, Sql, AzureCloud, plus service-specific tags.
Effective rulesNetwork Watcher → Effective security rules shows the merged result for a NIC.

Connectivity services

ItemWhat to remember
Azure BastionPaaS jump host in AzureBastionSubnet (/26+). RDP/SSH over TLS 443 in the browser; VMs need no public IP.
Service endpointExtends the VNet identity to a PaaS service over the Azure backbone. Still uses the service's public IP; add the subnet to the service firewall.
Private endpointA private IP in your subnet for a PaaS service. Disable public access to force it. Needs a private DNS zone to resolve.
Private Link DNSprivatelink.blob.core.windows.net etc., linked to the VNet. Without the link, clients resolve the public IP.
VPN GatewaySite-to-site, point-to-site, or VNet-to-VNet. GatewaySubnet, a gateway SKU (VpnGw1+ for production), and a local network gateway for each site.
Active-activeTwo gateway instances and two tunnels; needs --enable-active-active and BGP for automatic failover.
ExpressRoutePrivate dedicated circuit; needs a gateway with the right SKU and a route filter. Does not traverse the internet.
Virtual WANManaged hub-and-spoke with transitive routing, VPN, ExpressRoute, and firewall as a service.

Name resolution

ItemWhat to remember
Azure DNSPublic zones. Delegate with an NS record from the registrar. Alias records can point at a public IP, Traffic Manager, or Front Door and follow IP changes.
CNAME at apexNot allowed. Use an alias A/AAAA record instead.
Private DNS*.internal style zones linked to VNets. autoregistration records VM names automatically.
Resolution orderPrivate zone (linked VNet) → Azure-provided DNS → custom DNS servers on the VNet.
Cross-VNetA private zone must be linked to every VNet that must resolve it. Peering alone is not enough.

Load balancing and delivery

ItemWhat to remember
Load Balancer SKUBasic (open, no SLA, no zones) vs Standard (secure by default, SLA 99.99%, zones). Standard adds HA ports rules (all ports and protocols) for NVAs and clustered appliances.
Public vs internalPublic LB has a public frontend IP; internal LB uses a private IP in a subnet. Both route by 5-tuple hash.
Health probeTCP, HTTP, or HTTPS. Failed probes remove the instance; there is no automatic re-add without a passing probe.
Session persistenceNone (5-tuple) · Client IP (2-tuple) · Client IP and protocol (3-tuple).
Outbound rulesStandard LB provides outbound SNAT; without a rule or NAT gateway, VMs have no outbound internet.
Application GatewayLayer 7 reverse proxy: path-based routing, TLS termination, cookie affinity, autoscaling (v2), and WAF (OWASP CRS; Detection vs Prevention — tune exclusions before prevention). Needs a dedicated subnet.
Front DoorGlobal anycast HTTP(S) entry: latency routing, priority failover, caching, WAF at the edge. Backends can be App Service, App Gateway, or any public endpoint.

Troubleshooting

ToolUse it for
IP flow verifyIs this 5-tuple allowed or denied, and which NSG rule decided?
Next hopWhere would traffic from this VM to that IP go? Shows the effective route type.
Connection troubleshootEnd-to-end reachability test between a VM and an endpoint, with latency and hops.
Effective routesMerged system, BGP, and UDR routes for a NIC.
Connection MonitorContinuous, alerting reachability tests across VMs and endpoints.
Packet captureCapture at the VM NIC (or via NSG flow logs) for deep analysis.

Azure Monitor data

ItemWhat to remember
MetricsNumeric time series, near real time. Platform metrics are automatic; guest metrics need the Azure Monitor Agent and a data collection rule.
Metric retention93 days at minute granularity. Extend by archiving to storage or sending to Log Analytics.
Activity logControl-plane events (who did what to which resource). Kept 90 days; export to Log Analytics, storage, or Event Hubs for longer.
Resource logData-plane and service-specific logs (“diagnostic logs” in older docs). Off by default; needs a diagnostic setting.
Diagnostic settingOne per resource (up to five) sending to Log Analytics, storage, Event Hubs, or a partner. Subscriptions can use a policy to deploy them at scale.
Log AnalyticsWorkspace-based log store queried with KQL. Retention: 30 days interactive by default, up to 730; archive tier beyond that.
Workspace-scoped queryworkspace('name').Table queries another workspace without leaving yours.
VM insightsGuest performance and dependency map. Needs AMA + DCR; the legacy MMA agent is retired.
Container insightsNode, pod, and container metrics and logs for AKS and Arc.

Alerts

ItemWhat to remember
Signal typesMetric · log (Log Analytics) · activity log · smart detection · Prometheus (managed).
Metric alertThreshold on a metric, evaluated every 1 minute by default. Multi-resource alerts apply one rule to many resources with dimensions.
Log alertKQL result count or value. Can use dimensions to split per computer. Minimum frequency 1 minute (5 for some).
Activity log alertTriggered by control-plane events such as service health or resource delete.
Action groupReusable set of notifications (email, SMS, voice, push) and actions (Logic App, Function, webhook, Automation Runbook, Event Hubs, ITSM).
Alert processing ruleSuppress or route alerts during a maintenance window, or apply an action group to a filtered set.
Severity0 critical → 4 verbose. Severity is part of the alert rule, not the action group.
StateNew · Acknowledged · Closed. Fired alerts auto-resolve when the condition clears (metric alerts).

Monitoring agents

ItemWhat to remember
AMAAzure Monitor Agent replaces MMA/OMS. One agent, many DCRs.
DCRData collection rule: what to collect, how to transform it, where to send it. Associated with VMs, VMSS, or Arc servers.
Multiple DCRsSeveral DCRs can apply to one VM; the union of their data sources is collected.
Syslog / Windows eventsConfigured in the DCR, not on the agent.
AssociationDCR associations can be created per VM or at scale with policy.

Network Watcher

ToolUse it for
IP flow verifyAllow/deny decision and the NSG rule responsible.
Next hopEffective route and next-hop type for a destination.
Connection troubleshootOne-shot reachability test with latency.
Connection MonitorContinuous tests with alerts, across VMs, endpoints, and ExpressRoute.
Packet captureCapture traffic on a VM NIC or through an NSG.
Flow logsNSG flow logs (now VNet flow logs) record allowed and denied flows to storage.
TopologyVisual network map for a resource group.

Backup

ItemWhat to remember
Vault choiceRecovery Services vault for IaaS VMs, SQL in VM, Azure Files, SAP HANA. Backup vault for blobs, managed disks, PostgreSQL, AKS, and vaulted (enhanced) policies.
RedundancyLRS, ZRS, GRS (default). Cross-region restore must be enabled on the vault before you need it.
VM backupSnapshot-based, application-consistent where possible. Policy sets frequency (daily/weekly), instant restore tier, and retention.
Enhanced policyMore frequent backups (every 4 hours), multiple daily recovery points, longer instant restore.
RetentionDaily, weekly, monthly, yearly rules. The longest matching rule wins; retention is calculated from the backup time.
Restore optionsReplace existing · Create new (alternate location) · Restore disks · File recovery (mount a recovery point as a drive, 12-hour limit).
Azure Files backupSnapshot-based; the share must be in a storage account the vault can reach.
Blob backupOperational backup (local, continuous, 1–360 days) or vaulted backup (copy to a vault, cross-region).
Soft delete14 days by default for backup items; always enable enhanced soft delete.
SecurityMulti-user authorization, immutable vault, MFA for critical operations, alert on delete.

Site Recovery

ItemWhat to remember
PurposeDisaster recovery replication to a secondary region (or on-premises to Azure), with orchestrated failover.
ReplicationContinuous, per VM, into a cache storage account in the target region. RPO typically 5–15 minutes.
Recovery planGroups VMs, adds pre/post scripts and manual steps, and sets boot order.
Test failoverIsolated test network, no impact on production, no replication stop. Always test before a real failover.
FailoverPlanned (no data loss), unplanned (possible data loss), or test. Commit or re-protect afterwards.
TargetsAzure VMs, Hyper-V, VMware, physical servers. Requires the Mobility service agent on each source.
